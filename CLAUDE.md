# HammerTrack — Project Handoff

## What This Is
Mobile-first asset tracking SaaS for construction companies. Competes with Tenna at lower price.
Tracks vehicles (OBD2), heavy equipment (GPS), personnel, small tools (Bluetooth) on a live map.
Owner: Brian Dillard / Dillard Construction Group (Greenville, SC area).

The FIRST scan summons the OS Bluetooth prompt, so a one-time card explains it first (`ht_ble_primer`) — a cold prompt earns a Deny that kills the feature on that phone forever. **Ship-check pass the same night caught five real ones:** the plugin's `initialize()` RE-REQUESTS the OS permission on every call, so restarting the scan each window would have thrown the system dialog over the person every 20 s and earned the second denial Android treats as permanent (now: initialize once per mount, a refusal is final for the session, `isEnabled()` first — Android's `startScan` is a silent no-op with the adapter off, so the status line used to claim it was listening forever); the card's "queue behind the location primer" check read a flag the primer raises a render LATER, so the card was created under the location sheet and burnt (now deferred a tick + the `ht:primer-done` listener); leaving the screen now STOPS the radio (Android does not unregister a scan, it only stops delivering results — a scan armed in a pocket is pure battery); a phone that has not moved 25 m and hears the same tags repeats itself at most every 5 min (a truck parked with five tagged tools was about to write ~1,800 near-identical `asset_locations` rows a day into the table the ledger scans); and the gateway can no longer REVIVE a stopped share — `pushPhoneLocation({reactivate:false})` answers 409 and the gateway stands down, because "Stop sharing" has to mean it.
